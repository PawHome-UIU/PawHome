STAFF DASHBOARD

  URL       /staff

PETS MANAGEMENT
--------------------------------------------------------------------------------
  URL       /staff/pets
  FILE      src/pages/staff/PetsManagementPage.jsx
  WHAT      The shelter's pet list. Where a new rescue is entered.
  ON SCREEN A searchable table of pets with status badges.
            Buttons: "Add Pet" (opens AddPetModal), "Edit" / "Edit Profile"
            (opens the SAME modal in edit mode).
            A success pop-up confirms the save.
  USES      StaffLayout, StatusBadge, DataTable, Card, Button, Input, Modal,
            Dropdown, AddPetModal, SuccessModal
  DATA      src/data/staff.js -> STAFF_PETS
  HOOKS     useState, useMemo (search + filter)
  >>> ONE MODAL DOES ADD AND EDIT. It just changes its title and the save
      button text ("Add pet" / "Save changes"). Two separate modals would be
      the same code written twice.

APPLICATIONS LIST
--------------------------------------------------------------------------------

  FILE      src/pages/staff/ApplicationsPage.jsx
  WHAT      Every adoption application waiting for a decision.
  ON SCREEN Number tiles, tabs (Pending / Approved / Declined), a table of

  USES      StaffLayout, StatTile, DataTable, Button, Tabs

--------------------------------------------------------------------------------
APPLICATION REVIEW
--------------------------------------------------------------------------------
  URL       /staff/applications/:id      example: /staff/applications/1
  FILE      src/pages/staff/ApplicationReviewPage.jsx
  WHAT      One application in full, with the adopter's answers, so staff can
            decide. THE MOST IMPORTANT PAGE IN MY PART.
  ON SCREEN The adopter's details and quiz answers, the pet they applied for.
            Buttons: "Approve"  -> sets decision to APPROVED, shows a success
                                   pop-up, then goes back to the list.
                     "Decline"  -> opens DeclineApplicationModal, which asks
                                   for a REASON first.
  USES      StaffLayout, Card, Button, Modal, StatusBadge, SuccessModal,
            DeclineApplicationModal
  DATA      src/data/staff.js -> APPLICATION_DETAIL
  HOOKS     useState (decision), useNavigate (back to the list after deciding)
  >>> WHY DECLINE ASKS FOR A REASON AND APPROVE DOES NOT:
      Declining is the decision the adopter will question. Recording why means
      staff can explain it later. Approving needs no explanation.

--------------------------------------------------------------------------------
BOARDING
--------------------------------------------------------------------------------
  URL       /staff/boarding
  FILE      src/pages/staff/BoardingPage.jsx
  WHAT      Boarding requests from adopters, and current stays.
  ON SCREEN Number tiles, tabs (Requests / Active), request cards.
            Buttons: "Accept"           approve the booking
                     "Accept & Assign"  approve AND give it a kennel in one step
                     "Decline"          opens DeclineBoardingModal (asks a reason)
                     "Cancel"           close without doing anything
            Also "Post update" via PostBoardingUpdateModal, to message the owner.
  USES      StaffLayout, StatTile, Card, Button, Modal, Tabs, SuccessModal,
            PostBoardingUpdateModal, DeclineBoardingModal
  DATA      src/data/staff.js -> BOARDINGS, BOARDING_REQUESTS
  HOOKS     useState
  >>> "Accept & Assign" exists because accepting and then assigning a kennel
      as two separate clicks was extra work for no reason.

--------------------------------------------------------------------------------
SETTINGS
--------------------------------------------------------------------------------
  URL       /staff/settings   AND   /admin/settings   AND   /app/settings
  FILE      src/pages/SettingsPage.jsx
  WHAT      ONE settings page shared by all three portals.
  ON SCREEN Tabs: Profile, Password, Notifications.
            Buttons: "Save changes", "Update password".
  USES      AdminLayout, StaffLayout, AdopterLayout (it imports ALL THREE),
            Card, Button, Input, Tabs, SuccessModal, Textarea
  HOOKS     useLocation (reads the web address), useState
  >>> HOW ONE FILE SERVES THREE PORTALS -- the best question in my part:
      useLocation() tells it whether the address starts with /admin, /staff
      or /app, and it wraps itself in the matching layout. The content is
      identical for everyone, so three copies would mean fixing every bug
      three times.

################################################################################
3.  THE UI KIT   --  MY MOST IMPORTANT WORK
################################################################################

src/components/ui/  --  10 files used by all 29 pages in the project.

  Button.jsx        Every button in the app. Has variants (primary, outline,
                    danger) and sizes.
  Input.jsx         Text boxes.
  Field.jsx         The biggest one. Exports Select, Textarea, Segmented,
                    ChipGroup and FileDrop -- all the form controls that are
                    not a plain text box.
  Checkbox.jsx      Tick boxes.
  Dropdown.jsx      Select menus. Uses useEffect to close when you click away.
  Card.jsx          The white rounded box used everywhere.
  Modal.jsx         The pop-up frame: dark background, centred box, closes on
                    the Escape key (that is the useEffect inside it).
                    EVERY modal in the project is built on this one file.
  SuccessModal.jsx  The green "that worked" confirmation. Built from Button.
  Tabs.jsx          Tab switching inside a page.
  Accordion.jsx     Expand / collapse sections (used on the FAQ).

  PortalShell.jsx   components/portal/PortalShell.jsx
      The shared frame for ALL THREE logged-in portals: sidebar, top bar,
      content area. AdminLayout, StaffLayout and AdopterLayout are each a
      few lines that pass it different menu items.
      >>> IF THE TEACHER ASKS "WHY DO ALL THREE PORTALS LOOK THE SAME?" --
          this is the file. One shell, three menus.

  PanelCard.jsx     components/portal/PanelCard.jsx
      A titled panel used inside those portals.

WHAT TO SAY ABOUT THE UI KIT:
  "Nobody on our team hand-writes a button. Every input, modal and card on
   all 29 screens comes from these 10 files. Change the button style once and
   it changes everywhere."

MY RULES AS THE OWNER:
  * No colour codes like #4a7c59 inside these files. Everything uses the "pw"
    palette in tailwind.config.js.
  * I ADD props, I never RENAME them -- renaming would silently break every
    page the other two wrote.
  * If someone needs a new button style, I add it here. They never copy
    Button.jsx into their own folder.
