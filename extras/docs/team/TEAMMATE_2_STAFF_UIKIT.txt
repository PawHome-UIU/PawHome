3.  YOU OWN THE UI KIT  --  extra responsibility
--------------------------------------------------------------------------------

Both other teammates import Button, Input, Modal, Field, etc. on every page.
That means:

  * BUILD THE UI KIT FIRST, before your staff pages. The others are blocked
    until Button and Input exist and are stable. Push them on day one.

  * A BREAKING CHANGE BREAKS TWO OTHER PEOPLE. If you rename a prop
    (variant -> kind, say), you have just broken every page they wrote.
    -> Add new props, do not rename old ones.
    -> If you MUST rename, announce it in the group chat first and say which
       files they need to update.

  * ADD, DO NOT FORK. If Teammate 1 asks for a "ghost" Button variant, add it
    to Button.jsx. Never let them copy Button into their own folder -- that is
    how a design system dies in week two.

  * DOCUMENT THE PROPS. One comment block at the top of each component listing
    what it accepts. It saves you answering the same question twice a day.

  * NEVER put a raw hex colour in a ui/ component. Everything comes from the
    `pw` palette in tailwind.config.js, so one palette change updates the
    whole app.


--------------------------------------------------------------------------------
4.  ONE-TIME SETUP
--------------------------------------------------------------------------------

Prerequisite: Faiyaj must have pushed the repo to GitHub first.

  git --version
  node -v            # need 20+
  docker --version

Clone and branch:

  # macOS / Linux / Git Bash
  cd ~/Documents
  git clone https://github.com/FaiyajJarif/Pawhome.git
  cd Pawhome

  # Windows Command Prompt
  cd %USERPROFILE%\Documents
  git clone https://github.com/FaiyajJarif/Pawhome.git
  cd Pawhome

Then, identically on every OS:

  git config user.name  "Your Name"
  git config user.email "your@email.com"

  git checkout -b feature/staff-ui
  git push -u origin feature/staff-ui

Install and run:

  cd frontend
  npm install
  npm run dev                    -> http://localhost:5174

  # in another tab, for the API:
  cd ..\docker    (Windows)  |  cd ../docker    (macOS)
  docker compose up -d
  cd ..\backend   (Windows)  |  cd ../backend   (macOS)
  mvnw.cmd spring-boot:run   (Windows)  |  ./mvnw spring-boot:run   (macOS)

5.  DAILY WORKFLOW  --  do this every single day
--------------------------------------------------------------------------------

START of a session -- pull main into your branch BEFORE you write anything:

  git checkout feature/staff-ui
  git fetch origin
  git merge origin/main

  (Doing this daily means you resolve 2 small conflicts instead of 40 large
   ones at the end. This is the single most important habit in this list.)

WHILE WORKING -- commit small and often:

  git add src/components/ui/Button.jsx
  git commit -m "ui: add ghost variant to Button"

  Commit message prefix is your scope, so `git log` is readable:
      ui: ...      staff: ...      settings: ...

  PUSH UI-KIT CHANGES IMMEDIATELY. The other two are waiting on them; do not
  sit on Button.jsx for three days.

END of a session -- always push, even if unfinished:

  git push

6.  THE ROUTING FILE  --  the ONE place all three of you collide
--------------------------------------------------------------------------------

src/App.jsx is shared. Everyone adds routes to it, so it WILL conflict.

Rule: only ever touch YOUR marked block. Never reformat or reorder the file.

  {/* ---- TEAMMATE 2: staff console + settings ---- */}
  <Route path="/staff"          element={<StaffLayout />}>
    <Route index                element={<StaffDashboard />} />
    <Route path="pets"          element={<PetsManagementPage />} />
    ...your routes only...
  </Route>
  {/* ---- END TEAMMATE 2 ---- */}

If git reports a conflict in App.jsx, KEEP BOTH SIDES:

  git merge origin/main
  # open src/App.jsx, delete the <<<<<<< ======= >>>>>>> lines,
  # keep BOTH your routes and theirs
  git add src/App.jsx
  git commit
  npm run dev        # confirm the app still loads before pushing
  git push

--------------------------------------------------------------------------------
10. IF SOMETHING BREAKS
--------------------------------------------------------------------------------

  "Vite: failed to resolve import"
        A file you imported was deleted or renamed by someone else.
        -> git fetch origin && git merge origin/main, then fix the import path.

  Someone says "you broke my page"
        You probably renamed a prop in ui/. Check `git log src/components/ui/`.
        Add the old prop back as an alias, then coordinate the rename properly.

  "Network Error" / API unreachable in the browser
        The backend is not running. -> cd backend && ./mvnw spring-boot:run
        Check the port is 8081 in src/lib/config.js.

  Merge conflict you do not understand
        git merge --abort           # nothing is lost, you are back where you were
        Then ask the group before retrying. Never force-push to fix a conflict.

  You committed to main by accident
        git branch feature/staff-ui         # save your work onto your branch
        git checkout feature/staff-ui
        (then tell Faiyaj -- do NOT push main)

  NEVER RUN:  git push --force        on a shared branch. It deletes other
                                      people's commits.
